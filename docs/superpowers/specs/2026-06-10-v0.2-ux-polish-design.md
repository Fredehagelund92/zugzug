## Problem

An audit of the app's five primary routes (Sources, Triage, MasterTables, Settings, Dashboard) surfaced ~25 user-facing gaps. The 12 items below are the high-impact subset: real safety issues on destructive actions, an RBAC viewer regression introduced by PR #90, missing async feedback, and a handful of consistency gaps. Each fix is small; the value is shipping them together so the patterns (confirm, busy state, loading skeleton, flash, health check) get established once.

## Decisions (locked during brainstorming)

1. **One shared `<ConfirmDialog>` primitive**, not per-screen inline banners. Replaces the raw `window.confirm` at `TablePane.tsx:757` too.
2. **One `useAsyncAction()` hook** + `loading` prop on existing `<Button>`. No per-site `useState` boilerplate.
3. **Standardize flash durations** with one `FLASH_DURATION_MS` constant + `useFlash(label)` helper. Do not build a real toast queue.
4. **Real connection health check** via `GET /api/health/connections` (pings warehouse + Postgres), not a hardcoded "connected" badge.

## New primitives — public surfaces

### `<ConfirmDialog>` (`app/src/components/ConfirmDialog.tsx`)

```ts
type ConfirmDialogProps = {
  open: boolean;
  title: string;
  body?: React.ReactNode;
  confirmLabel?: string;       // default "Confirm"
  cancelLabel?: string;        // default "Cancel"
  danger?: boolean;            // red confirm button
  onConfirm: () => void | Promise<void>;
  onCancel: () => void;
};
```

Behavior: portal-mounted, backdrop click cancels, Esc cancels, Enter confirms when focus is on the confirm button, focus trap inside the dialog, autofocus on cancel button (so Enter doesn't accidentally confirm).

### `useAsyncAction()` (`app/src/hooks/useAsyncAction.ts`)

```ts
type AsyncAction<TArgs extends unknown[]> = {
  run: (...args: TArgs) => Promise<void>;
  isPending: boolean;
  error: Error | null;
  reset: () => void;
};

function useAsyncAction<TArgs extends unknown[]>(
  fn: (...args: TArgs) => Promise<unknown>,
): AsyncAction<TArgs>;
```

Behavior: `run` rejects re-entry while `isPending`. Errors caught and surfaced via `error`. `reset()` clears error/pending so caller can retry cleanly. `<Button loading={action.isPending}>` already shows a spinner.

### `useFlash()` (`app/src/hooks/useFlash.ts`)

```ts
type Flash = {
  message: string | null;
  variant: 'success' | 'error';
  show: (msg: string, variant?: 'success' | 'error') => void;
};

function useFlash(): Flash;
```

Uses one shared `FLASH_DURATION_MS = 2800` constant (chosen as median of the existing 2.6/2.8/3.2s values). Replaces the per-screen `useState<string | null>` + `setTimeout` pattern at known sites: Sources `flash`, Sources `derived`, Triage commit flash, plus the new H6/M5 sites.

### `GET /api/health/connections` (`server/src/server.ts`)

Request: none. Response:

```ts
type HealthResponse = {
  warehouse: { status: 'ok' | 'error' | 'disabled'; lastCheckedAt: string; error?: string };
  postgres:  { status: 'ok' | 'error';              lastCheckedAt: string; error?: string };
};
```

- `warehouse.status = 'disabled'` when `ATTACH_WAREHOUSE=false`.
- `warehouse.status = 'ok'` when a trivial `SELECT 1` against the warehouse adapter succeeds; `'error'` otherwise with `error` set to the exception message.
- `postgres.status = 'ok'` when `SELECT 1` against the Postgres pool succeeds.
- Auth: same session gate as other `/api/*` routes; no role gating (every signed-in user can see workspace health).
- Caching: server caches results for 5 seconds to avoid hammering the warehouse on every Settings render.

Settings/Connections cards render the real status + a relative "last checked Ns ago" line. A small refresh icon next to each card retriggers the check (bypassing the 5s cache via a `?force=1` query param).

## Out of scope (explicit)

- **Real toast queue.** `useFlash` keeps per-screen state; not a global queue. If two flashes fire on the same screen, the second replaces the first. Sufficient for current usage.
- **Health checks beyond warehouse + Postgres.** No checks for Snowflake adapter (PR C territory), scheduler liveness (PR A scope), or third-party APIs.
- **All 9 Low items from the audit.** Defer to a v0.3 polish round: flash-duration full sweep (already partially addressed by `useFlash`), dimension-link in wire-success, Dashboard row keyboard reach, error-message phrasing, `currentUser.email` const, Token form Esc-from-body, Triage `A` dead-key, Auto-match confirm on 90+ sweep, MatchMode skip undo affordance.
- **Cross-screen consistency audit for other surfaces.** Audit only covered the 5 primary routes; modals, popovers, and admin-only surfaces (super-admin if it lands) are not touched here.
- **Issue filing.** This spec is the source of truth for the 12 fixes; no need to file 12 child issues unless we want them on a board. Title commits with the H#/M#/K# code so the spec is greppable from git log.

## Risks worth flagging

- **`useAsyncAction` re-entry guard.** If a caller invokes `run` while `isPending`, the call is silently dropped. This is the desired behavior for click-spam, but document it clearly so a future caller doesn't think `run` always fires.
- **5-second health-check cache.** Avoids hammering MotherDuck on every Settings render but means a connection that just broke can show "ok" for up to 5s. Acceptable — the refresh icon gives a manual override.
- **Replacing `window.confirm` changes the keyboard interaction.** Native confirm intercepts Enter/Esc at the OS level; the custom dialog must trap focus and handle keys in JS. Test with screen readers if accessibility coverage is a goal (it's listed as a Low in the audit, not enforced here).
