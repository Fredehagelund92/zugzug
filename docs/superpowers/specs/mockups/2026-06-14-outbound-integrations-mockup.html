Webhook signing recipe

Verify HMAC signatures · permanent reference

copy any time · no secret rotation needed

The same snippet customers receive inside the secret-reveal modal. Kept here so an operator debugging a signature failure months later doesn't need to rotate a key just to retrieve it.

// Node 18+ — same as the modal; absolute skew check + length-checked hex. import { createHmac, timingSafeEqual } from "node:crypto"; export function verifyZugzugSignature(rawBody, header, secrets) { const parts = {}; for (const seg of header.split(",")) { const eq = seg.indexOf("="); if (eq > 0) parts[seg.slice(0, eq).trim()] = seg.slice(eq + 1).trim(); } if (!parts.t || !parts.kid || !parts.v1) return false; const skew = Math.abs(Date.now() / 1000 - Number(parts.t)); if (!Number.isFinite(skew) || skew > 300) return false; const m = /^sha256=([0-9a-f]{64})$/.exec(parts.v1); if (!m) return false; const provided = Buffer.from(m[1], "hex"); const secret = parts.kid === "previous" ? secrets.previous : secrets.current; if (!secret) return false; const expected = createHmac("sha256", secret) .update(parts.t + "." + rawBody).digest(); if (expected.length !== provided.length) return false; return timingSafeEqual(expected, provided); }
absolute skew check · length-bounded hex · two-key during 24h rotation grace
Where canonical lives

Each commit folds approved drafts into dim_* / map_* tables in this workspace's Postgres. Pull API serves directly from those tables — there is no warehouse round-trip per call. For a single-file copy (dbt seed, ad-hoc), each dimension still exposes a /snapshot.parquet link in its Tables view.

// Two-key verify: current always; previous valid 24h post-rotation. // The same recipe lives on the Pull API page → Webhooks tab — no need to // rotate a secret to retrieve it later. import { createHmac, timingSafeEqual } from "node:crypto"; export function verifyZugzugSignature(rawBody, header, secrets) { // "t=<unix>,kid=<current|previous>,v1=sha256=<hex>" const parts = {}; for (const seg of header.split(",")) { const eq = seg.indexOf("="); if (eq > 0) parts[seg.slice(0, eq).trim()] = seg.slice(eq + 1).trim(); } if (!parts.t || !parts.kid || !parts.v1) return false; // Reject clocks more than 5 min off in EITHER direction. const skew = Math.abs(Date.now() / 1000 - Number(parts.t)); if (!Number.isFinite(skew) || skew > 300) return false; // v1 = "sha256=<64-hex>" — length + alphabet enforced before hex decode. const m = /^sha256=([0-9a-f]{64})$/.exec(parts.v1); if (!m) return false; const provided = Buffer.from(m[1], "hex"); const secret = parts.kid === "previous" ? secrets.previous : secrets.current; if (!secret) return false; const expected = createHmac("sha256", secret) .update(parts.t + "." + rawBody).digest(); if (expected.length !== provided.length) return false; // belt-and-suspenders return timingSafeEqual(expected, provided); }

Delivery contract
  • At-least-once — subscribers must dedupe on X-Zugzug-Event-Id.
  • 10s deadline — enforced by AbortController; respond 2xx first, work later.
  • Per-commit grain — one event per atomic dim version.
  • Auto-disable when the last 50 deliveries all DLQ'd (no success between).
  • URL snapshot — each delivery POSTs the URL recorded at enqueue; URL edits don't redirect in-flight.
  • Rotation grace — 24h window where kid=previous is also accepted.

Why one bus
Two readers, one source. Pull API and webhooks never drift. The event INSERT is inside the canonical-commit tx — if the event fails, the commit fails. No silent drop.
Why per-commit
A 500-row import is one event with a 1.2 KB diff summary, not 500 separate POSTs. Subscribers who want row detail call the Pull API; for retired/merged keys they call /tombstones.
Why scheduler-as-host
The dispatcher registers with the scheduler for lifecycle (boot/drain/stop, audit on failure) but runs its OWN concurrency model — the stock per-tenant sequential loop is sized for fast Postgres work, not 10s HTTP. Claim is a short tx that returns connections to the pool BEFORE any fetch.
