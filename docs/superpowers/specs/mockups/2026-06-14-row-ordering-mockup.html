Reference dims keep their derived sort (variants → label). Workflow-stage dims opt into a stored position column with drag-to-reorder, "insert above/below" that actually positions, and a banner that warns when view-sorts hide the persisted order.

appendix · schema diff

One migration. Adds ordering_mode + last_rebalanced_at to the registry (with a CHECK constraint), then walks the registry to add position BIGINT + two partial indexes to each dim_* table.

0021_row_ordering.sql drizzle 
-- registry
ALTER TABLE "zugzug_app"."dimension"
  ADD COLUMN ordering_mode VARCHAR
    NOT NULL DEFAULT 'derived',
  ADD COLUMN last_rebalanced_at TIMESTAMP,
  ADD CONSTRAINT dimension_ordering_mode_chk
    CHECK (ordering_mode IN ('derived', 'manual'));

-- every existing dim_* table.
-- dim_table is qualified ("zugzug.dim_X");
-- format('%I', ...) would double-quote the
-- whole string, so we split + use two %I.
DO $$
DECLARE
  r            RECORD;
  dot_pos      INT;
  schema_name  TEXT;
  table_name   TEXT;
BEGIN
  FOR r IN SELECT id, dim_table
           FROM "zugzug_app"."dimension"
  LOOP
    dot_pos     := position('.' IN r.dim_table);
    schema_name := substring(r.dim_table
                     FROM 1 FOR dot_pos - 1);
    table_name  := substring(r.dim_table
                     FROM dot_pos + 1);

    EXECUTE format(
      'ALTER TABLE %I.%I
         ADD COLUMN IF NOT EXISTS
         position BIGINT',
      schema_name, table_name);

    -- read path; partial so derived dims
    -- pay nothing.
    EXECUTE format(
      'CREATE INDEX IF NOT EXISTS %I
         ON %I.%I (position)
         WHERE position IS NOT NULL',
      'dim_' || r.id || '_position_idx',
      schema_name, table_name);

    -- backstop: tied positions never
    -- persist (dim ids are globally
    -- unique → unique on `position`
    -- alone is sufficient).
    EXECUTE format(
      'CREATE UNIQUE INDEX IF NOT EXISTS
         %I ON %I.%I (position)
         WHERE position IS NOT NULL',
      'dim_' || r.id || '_position_uniq',
      schema_name, table_name);
  END LOOP;
END $$;

notes

Interactions worth calling out

Drag is the only mutator of position. Clicking a column header never writes to canonical.

Bulk CSV imports append. The import loop is wrapped in a single pgTx; nextPos is read once and each new row gets nextPos + 1024 * local_i (incremented on successful insert).

Two users drag the same row. SERIALIZABLE tx serializes the writes; the unique partial index is the backstop. The loser's 409 handler issues an immediate refetch — stale UI is bounded to one round-trip, not the focus/window-blur cadence. Live cross-client fan-out is out of scope (tracked in E1).

dbt & HTTP-friendly. ORDER BY position NULLS LAST works in both modes for dbt. The HTTP list response gains a per-row position?: string | null + dim-level nextPosition?: string | null (string, not number — bigint exceeds JS safe-int range).

canView in manual mode. Drag handle column visible but disabled with "Read-only access" tooltip. Position context items hidden. Banner + Restore + Dismiss remain — they mutate the user's own GridLayoutConfig.sort only. In derived mode no drag column at all.

Keyboard A11y. Drag handle is a focusable button. ⌘⇧↑ / ⌘⇧↓ reorders by one (matches Linear/Notion; avoids Safari's Alt-arrow history nav). ⌘⇧⤒ / ⌘⇧⤓ jump to top/bottom. Polite aria-live announces "Moved Trial to position 3 of 7".

Rollback is a flip. Set ordering_mode = 'derived' and the old projection returns. position column stays — nullable, cheap, nothing reads it.
